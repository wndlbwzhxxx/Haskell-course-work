# Metro Pathfinder — Визуализатор маршрутов на Haskell

Курсовая работа по дисциплине «Функциональное программирование»: консольное приложение на языке **Haskell** для поиска и визуализации кратчайших маршрутов в транспортных сетях (метрополитен, железные дороги). Программа загружает схему из JSON, строит взвешенный граф, находит кратчайший путь алгоритмом Дейкстры, сохраняет визуализацию схемы и маршрута в PNG через Graphviz и ведёт лог всех действий пользователя.

## Возможности

- **Загрузка схемы из JSON:** парсинг файлов транспортных сетей (станции, линии, координаты, пересадки) с помощью библиотеки `aeson` и проверкой ссылочной целостности.
- **Экспорт графа в JSON:** сохранение текущей схемы без потерь (станции, линии, координаты, пересадки).
- **Поиск кратчайшего пути:** алгоритм Дейкстры в чисто функциональном стиле на неизменяемых `Map` и `Set`; поддерживает ориентированные и неориентированные графы, восстанавливает маршрут от начальной до конечной станции.
- **Вычисление расстояний по координатам:** формула гаверсинусов (`haversineDistance`) для реальных расстояний между станциями по широте и долготе, округление до 0.1 км.
- **Пересадки:** рёбра с весом 0, выделяются зелёным цветом на визуализации.
- **Визуализация через Graphviz:** генерация DOT-описания и конвертация в PNG внешней программой `dot`/`neato`; станции — прямоугольники, рёбра подписаны расстояниями, найденный маршрут выделяется красным цветом и утолщённой рамкой.
- **Логирование с ротацией:** временные метки и уровни (`Info`, `Warning`, `Error`); при превышении 10 МБ старый лог сохраняется в `app.log.old`, основной очищается.
- **Консольное меню из 10 пунктов** с обработкой ошибок ввода, отсутствия загруженного графа и ненайденного пути.
- **Тестирование QuickCheck:** свойства для алгоритма Дейкстры и структуры графа (путь из станции в себя нулевой длины, неотрицательность весов, симметричность неориентированного графа, неотрицательность длины пути).

## Стек

- **Язык:** Haskell (GHC 9.6.6+)
- **Система сборки:** Stack
- **Библиотеки:** `aeson` (JSON), `containers` (`Map`, `Set`, `Sequence`), `text`, `time`, `directory`, `filepath`, `process`, `bytestring`, `QuickCheck`
- **Внешняя зависимость:** Graphviz (`dot`/`neato`) для генерации PNG
- **Формат данных:** JSON (вход/выход), PNG (визуализация), текстовый лог

## Требования

- Установленный [Stack](https://docs.haskellstack.org/) — автоматически загрузит нужную версию GHC и зависимости.
- **Graphviz** — установить вручную с [graphviz.org/download](https://graphviz.org/download/) и добавить `dot`/`neato` в системную переменную `PATH`.

## Установка и сборка

1. **Клонировать репозиторий**
```bash
git clone <ссылка_на_репозиторий>
cd route-visualizer
```

2. **Собрать проект** (Stack сам скачает GHC и зависимости)
```bash
stack build
```

3. **Запустить приложение**
```bash
stack run
```

## Формат входных данных

JSON-файл транспортной сети:

```json
{
  "name": "Название города",
  "lines": [
    {
      "name": "Название линии",
      "hex_color": "CD0505",
      "stations": [
        {
          "name": "Название станции",
          "order": 0,
          "lat": 53.20969,
          "lng": 50.13442,
          "transfers": ["Станция пересадки"]
        }
      ]
    }
  ]
}
```

**Обязательные поля:** `name` (станции), `order` (порядковый номер на линии).
**Необязательные:** `lat`/`lng` (для расчёта расстояний), `transfers` (пересадочные станции, вес ребра = 0).

Примеры готовых файлов: `samara.json`, `kiev.json`, `spb.json`. Исходные данные взяты из репозитория [morphey83/MetroAndDistrict](https://github.com/morphey83/MetroAndDistrict/blob/master/metro.all.json).

## Использование

При запуске отображается главное меню:

```
============================================
            METRO PATHFINDER
============================================
1. Load graph from JSON
2. Export graph to JSON
3. Find shortest path
4. List all stations
5. Find station by name
6. Visualize entire graph
7. Visualize path
8. View log
9. Clear log
0. Exit
============================================
Your choice:
```

1. **Загрузка графа (1):** введите путь к JSON-файлу; после загрузки выводится число импортированных станций.
2. **Экспорт графа (2):** сохраняет текущую схему в JSON без потерь.
3. **Поиск кратчайшего пути (3):** последовательно запрашивает начальную и конечную станции; выводит длину маршрута и последовательность станций. При пересадке расстояние `0.0 км`; при отсутствии пути — `No path found.`
4. **Список станций (4):** все станции в порядке загрузки.
5. **Поиск станции по части названия (5):** выводит все станции, содержащие подстроку.
6. **Визуализация графа (6):** сохраняет PNG всей схемы; станции — прямоугольники, рёбра подписаны расстояниями, пересадки зелёные.
7. **Визуализация пути (7):** сохраняет PNG с выделенным маршрутом (красный цвет, утолщённая рамка); требуется предварительно найти путь.
8. **Просмотр лога (8):** последние записи `app.log` с временными метками и уровнями.
9. **Очистка лога (9):** очищает `app.log` с подтверждением.
10. **Выход (0):** завершает программу.

## Архитектура

- **`Main.hs`** — точка входа: запуск меню, логирование старта и завершения.
- **`CLI/Menu.hs`** — `runCLI :: IO ()`, главное меню и обработчики (`loadGraphHandler`, `exportGraphHandler`, `findPathHandler`, `listStationsHandler`, `findStationHandler`, `visualizeGraphHandler`, `visualizePathHandler`, `viewLogHandler`, `clearLogHandler`). Не содержит логики алгоритмов.
- **`Graph/Types.hs`** — `StationName = Text`; `Weight` — `newtype` над `Double` с экземпляром `Num`; `Graph` — словарь станций (`Map StationId Station`) плюс список смежности (`Map StationId [(StationId, Weight)]`) и флаг `isDirected`; `PathResult = NoPath | Path { nodes :: [StationId], weight :: Weight }`.
- **`Graph/Loader.hs`** — `JsonStation`/`JsonLine`/`JsonMetro` с `FromJSON`/`ToJSON`; `loadGraphFromJSON`, `buildGraph`, `validateGraph` (проверка ссылочной целостности пересадок), `exportGraphToJSON`.
- **`Graph/Dijkstra.hs`** — `shortestPath` (обёртка), `dijkstra` (Map как приоритетная очередь, `Map.deleteFindMin`, релаксация соседей), `reconstructPath` (восстановление маршрута по таблице расстояний).
- **`Visualization/Render.hs`** — `toDot`/`toDotWithHighlight` (генерация DOT), `renderGraphToPNG`, `renderPathToPNG` (вызов внешнего `dot`).
- **`Logging/Logger.hs`** — `logMessage` (метка времени + уровень), `readLog`, `clearLog`, `checkLogSize` (10 МБ), `rotateLog` (переименование в `app.log.old`).

## Тестирование

```bash
stack test
```

Проверяемые свойства QuickCheck:
- путь из станции в саму себя имеет нулевую длину и состоит из одной станции;
- веса всех рёбер неотрицательны;
- неориентированный граф симметричен (есть A—B ⇒ есть B—A);
- длина кратчайшего пути неотрицательна.

Генератор `Arbitrary Graph` создаёт небольшие линейные графы без петель с симметричными рёбрами.

## Обработка ошибок

Программа не завершается аварийно при некорректном вводе:
- несуществующий файл, пустой путь, неверное название станции — выводится сообщение;
- отсутствие загруженного графа перед поиском пути или визуализацией — предупреждение и возврат в меню;
- отсутствие пути между станциями — `No path found.`;
- все ошибки фиксируются в логе с уровнем `Error` или `Warning`.
